## Phase 1 — Firebase Console 작업 (본인이 직접)

### 1. Firebase 프로젝트 생성

1. https://console.firebase.google.com 접속 (본인 Google 계정으로)
2. 「프로젝트 만들기」 클릭
3. 프로젝트 이름: `budgetbook-jwchoo` (혹은 본인이 원하는 이름)
   - 이게 URL의 일부가 됨 → `https://budgetbook-jwchoo.web.app`
4. Google Analytics 사용 여부: **사용 안함** 선택 (가계부에 불필요)
5. 「프로젝트 만들기」 클릭 → 1분 대기 → 완료

### 2. Authentication 활성화

1. 좌측 메뉴 「Build → Authentication」
2. 「시작하기」 클릭
3. 「Sign-in method」 탭
4. 「Google」 선택 → 「사용 설정」 토글 ON
5. 프로젝트 지원 이메일: 본인 이메일 선택
6. 「저장」

선택사항 — 가족 멤버 사전 등록:
- 「Users」 탭 → 「사용자 추가」 (이메일/임시 비번)
- 또는 마님이 처음 로그인할 때 자동 등록되도록 두기 (간편)

### 3. Firestore Database 활성화

1. 좌측 메뉴 「Build → Firestore Database」
2. 「데이터베이스 만들기」 클릭
3. **위치**: `asia-northeast3 (서울)` 선택 (한국 사용자 지연 최소)
4. **시작 모드**: 「테스트 모드로 시작」 선택 (개발 중)
   - ⚠️ 30일 후 자동 잠금. 그 전에 보안 규칙 작성 (Phase 2에서 함께 진행)
5. 「사용 설정」 클릭

### 4. Hosting 활성화

1. 좌측 메뉴 「Build → Hosting」
2. 「시작하기」 클릭
3. 안내 화면 그냥 「다음 → 다음 → 콘솔로 이동」
   - CLI 설치 안내는 무시. 우리는 코드에서 자동 배포 설정할 거.

### 5. Web 앱 등록 + 설정 키 받기

1. 좌측 톱니바퀴(⚙️) → 「프로젝트 설정」
2. 「내 앱」 섹션에서 「웹 앱 추가」 (`</>` 아이콘)
3. 앱 닉네임: `BudgetBook Web`
4. **Firebase Hosting 설정도 함께** 체크박스 ON
5. 「앱 등록」 클릭
6. 화면에 나오는 `firebaseConfig` 객체를 **그대로 복사**:
   ```js
   const firebaseConfig = {
     apiKey: "AIza...",
     authDomain: "budgetbook-jwchoo.firebaseapp.com",
     projectId: "budgetbook-jwchoo",
     storageBucket: "budgetbook-jwchoo.appspot.com",
     messagingSenderId: "123456789",
     appId: "1:123456789:web:abc..."
   };
   ```
7. 이 값을 본인 PC에 메모장으로 저장해두기. 곧 코드에 넣을 거.

### 6. 인증된 도메인 확인

1. Authentication → 「Settings」 → 「Authorized domains」
2. 자동으로 `localhost`, `budgetbook-jwchoo.firebaseapp.com`, `budgetbook-jwchoo.web.app`가 들어가 있을 것
3. 추가 도메인 등록 불필요 (커스텀 도메인 안 쓰니까)

## Phase 2 — 코드 통합 (Claude가 진행)

본인 firebaseConfig 받으면:

1. `firebase` npm 패키지 설치 (`app/package.json`)
2. `app/src/renderer/src/lib/firebase.ts` — Firebase 초기화 모듈
3. `app/.env.example` 작성 (다른 PC에서 작업 시 참고용)
4. Auth 컨텍스트(`AuthContext`) — React Context로 로그인 상태 관리
5. 로그인 화면 (`LoginView`) — Google 버튼 1개짜리 단순 화면
6. App.tsx — 로그인 안 한 사용자는 로그인 화면, 한 사용자는 기존 메인 화면
7. Firestore 보안 규칙 작성 — 가족 단위 접근만 허용

## Phase 3 — 데이터 레이어 교체

1. Firestore 컬렉션 스키마 설계 (transactions, categories, budgets, tags, accounts,
   recurring, savings_goals)
2. drizzle-orm 호출들을 Firestore SDK 호출로 교체
3. 기존 IPC 인터페이스(`window.api.*`)는 유지 — 내부 구현만 클라우드로
4. 트랜잭션 일관성 처리 (Firestore batch writes 활용)

## Phase 4 — PWA + 모바일 반응형 + 배포

1. `vite.config` PWA 플러그인 추가
2. `manifest.json` 작성 (앱 이름, 아이콘, 색상)
3. Service worker 등록
4. 모바일 layout 분기 (sidebar → bottom tab, 표 → 카드, 모달 → 풀시트)
5. `firebase deploy --only hosting`로 첫 배포
6. 본인 iPhone 또는 마님 iPhone에서 Safari 열고 「홈 화면에 추가」 테스트

## 무료 티어 한도 (Spark Plan, 신용카드 불필요)

- Firestore: 일 50K 읽기 / 20K 쓰기 / 20K 삭제 / 1GB 저장
- Auth: 무제한 사용자
- Hosting: 10GB 스토리지 / 일 360MB 다운로드
- 가족 2인 가계부 사용량은 한도의 1% 이하

비용 발생 트리거: Blaze 플랜(종량제) 명시 업그레이드를 본인이 직접 해야만 함. 자동
업그레이드 절대 없음 — 한도 초과 시 그냥 거절됨 (서비스 중단). 그래도 가계부 데이터량
기준 초과 가능성 거의 0.
